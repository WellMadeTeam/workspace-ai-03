# FR-023: Record Backend Request Signals

- **Status:** Active
- **Traces to:** [`SLI-01`](../../observability.md#sli-01)
- **Containers:** `backend`

## Behavior

When observability is enabled and configured, the backend shall record the duration of each HTTP request and export request logs and duration metrics to OpenObserve over OTLP/HTTP.

Each request log shall include a request ID, the route, the outcome, the duration in milliseconds, and the environment.

Each response shall include its request ID in the `X-Request-ID` header.

Each duration metric shall use the name `backend_http_request_duration_ms` and include the environment, route, and outcome.

The backend shall not include request or response bodies, query or reply text, authorization headers, secrets, or member identity in these signals.

Observability shall be disabled by default.

The product shall keep serving boards and queries when observability is disabled or OpenObserve is unavailable.

OpenObserve shall retain request logs and duration metrics for 30 days in staging and production.

## Acceptance Criteria

### AC-01

Given observability is enabled and configured, when the backend handles an HTTP request, then it exports a request log with a request ID, route, outcome, duration, and environment.

### AC-02

Given observability is enabled and configured, when the backend handles an HTTP request, then it records the request duration in the `backend_http_request_duration_ms` metric with environment, route, and outcome.

### AC-03

Given a request or reply contains text or a request contains authorization data, when the backend exports request signals, then those signals contain none of that content or data.

### AC-04

Given observability is disabled, when a member opens a board and sends a query, then the product works and does not export these request signals to OpenObserve.

### AC-05

Given OpenObserve is unavailable, when a member opens a board and sends a query, then the product continues to work.

### AC-06

Given request logs and duration metrics are available in OpenObserve, when a teammate checks staging or production data, then the data covers the previous 30 days.
