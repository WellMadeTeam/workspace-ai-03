# FR-022: Record The Core Task For Product Analytics

- **Status:** Active
- **Traces to:** [`US-17`](https://github.com/WellMadeTeam/workspace-ai-03/issues/277), [`VP-01`](../../research/value-proposition.md#vp-01), [`DEC-005`](../../decisions.md#dec-005), [`DEC-008`](../../decisions.md#dec-008)
- **Containers:** `backend`

## Behavior

When a member opens a board, creates an AI block, sends a query, receives a reply, connects blocks, or sends a query with an earlier AI reply as context, the backend shall record the corresponding event defined in [`docs/analytics.md`](../../analytics.md#the-events).

Each event shall carry only the fields listed in the analytics event table, including its `source` value.
The backend shall not send query text, reply text, member identity, block titles, or other free text to OpenPanel.
When analytics collection is disabled or OpenPanel is unavailable, the product shall keep serving the core task.

## Acceptance Criteria

### AC-01

Given a member opens a board, creates an AI block, sends a query, receives a reply, connects an earlier AI reply to another AI block, and gets a reply to a new query, when the event records reach OpenPanel, then they include `board_opened`, `ai_block_created`, `query_submitted`, `reply_received`, `connection_created`, `context_reuse_query_submitted`, and `context_reuse_reply_received` with the fields in [`docs/analytics.md`](../../analytics.md#the-events).

### AC-02

Given an event is sent to OpenPanel, when its properties are inspected, then `source` is exactly one of `web`, `usability-test`, or `smoke`, and a staging pipeline check can be marked `smoke`.

### AC-03

Given a query or reply contains free text, when its event is sent to OpenPanel, then the event carries no query text, reply text, personal data, or member identity.

### AC-04

Given analytics collection is disabled or OpenPanel cannot accept events, when a member completes the core task, then the product continues to work and show the same board behavior.
