# QR-02: Catch A Broken Board Or Query Change With The Checks

A developer can run the checks that cover the frontend entry point and the query flow from a clean checkout, and a change that breaks either fails them.

- **Status:** Active
- **Characteristic:** Maintainability
- **Sub-characteristic:** Testability
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

A team member who changes the code of the board or of the query flow.

### Stimulus

The change breaks the board's start-up or the storing of a query and its reply, and the member runs the checks before opening a pull request.

### Environment

A clean checkout of `main` on a developer's computer with the tools [`docs/setup.md`](../../setup.md) names, and no key for the LLM service provider.

### Artifact

The critical modules: the frontend entry point [`app/frontend/src/app/main.tsx`](https://github.com/WellMadeTeam/workspace-ai-03/blob/main/app/frontend/src/app/main.tsx), and the query flow in [`app/backend/src/routers/message.py`](https://github.com/WellMadeTeam/workspace-ai-03/blob/main/app/backend/src/routers/message.py) and [`app/backend/src/services/ai_service.py`](https://github.com/WellMadeTeam/workspace-ai-03/blob/main/app/backend/src/services/ai_service.py).

### Response

The checks run with one documented command for each of the `frontend` and the `backend`, without calling the LLM service provider, and report the broken behavior.

### Response Measure

From a clean checkout, the checks for both critical modules finish in under 2 minutes with no LLM key set, pass on `main`, and at least one check fails when the board no longer renders or when a sent query or its reply is no longer stored.
