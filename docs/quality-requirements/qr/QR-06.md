# QR-06: Complete The Main Brainstorming Task Without Help

A representative team using the shared board can record at least two design ideas and select one within 30 minutes without facilitator help.

- **Status:** Active
- **Characteristic:** Interaction Capability
- **Sub-characteristic:** Operability
- **Business importance:** High
- **Technical risk:** Medium

Operability is what UT-01 tests because the team must reach the main task's end state using the board; the observed unaided completion outcome shows whether it could do so without coaching.
The technical risk is Medium because the flow already exists, but the outcome and any facilitator help require human observation and cannot be established by product events alone.

## Scenario

### Source

A representative adult participant working with a software brainstorming team.

### Stimulus

The team begins the UT-01 main usability test task: brainstorm a simple service for organizing university events with LLM assistance.

### Environment

The shared-board condition of UT-01 uses the staging deployment on the university network, with an empty board and the same seeded task description for every primary team run.

### Artifact

The shared board's brainstorming and AI conversation capabilities.

### Response

The team records at least two distinct design ideas and selects one to develop further within the task limit, without facilitator help.

### Response Measure

The proportion `U / N` of eligible primary shared-board team runs recorded as `Unaided` is 100%, with at least three distinct representative participants in that condition, `N >= 1`, and a recorded main-task outcome for every eligible started run.
`U` counts runs reaching the main task's end state within 30 minutes without facilitator help; `N` includes all eligible runs that started the main task, including `Assisted`, `Failed`, and abandoned attempts.
A missing outcome prevents a verdict; an observed task failure does not make a run ineligible.
This is a binary bar with one planned shared-board team, so a pass describes the tested team rather than a population success rate.

## QRT-01

An observer checks the unaided main-task outcomes from the primary shared-board UT-01 sessions against the fixed QR-06 bar.

- **Status:** Active
- **Level:** manual
- **Runs at:** The main task and results inspection in [UT-01](../../usability-tests/ut-01/README.md) on the staging deployment.
- **Why Manual:** No command can judge whether a representative team reached the main task's end state without facilitator help, and this test reads no `SLI`.

### Procedure

1. Recruit and obtain the required consent and recordings for at least three representative adult participants in the primary shared-board condition, following the [UT-01 profile and protocol](../../usability-tests/ut-01/README.md#participant-profile).
2. Verify instrumentation before the first counted session, then run the main task on staging on the university network with the same seeded description, empty board, and 30-minute limit for each primary shared-board team.
3. Record each eligible team's end state, whether facilitator help was given, and its `Unaided`, `Assisted`, or `Failed` outcome once per team run; keep the participant session records linked to that run.
4. Read the shared-board main-task rows and aggregate `U`, `N`, distinct participant count, exclusions, and missing outcomes in [results.md](../../usability-tests/ut-01/results.md).
5. Apply the fixed criterion to the primary shared-board runs only; leave optional supplementary runs and the control condition outside `U` and `N`, and record the verdict in the [testing plan](../../project-plan.md#quality-requirement-testing-plan) during SPRINT-08.

**Pass when:** `U / N = 100%` for eligible primary shared-board main-task runs, `N >= 1`, at least three distinct representative participants have completed counted sessions in that condition, and every eligible started run has a recorded outcome.
