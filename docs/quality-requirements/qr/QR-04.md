# QR-04: Bring The Product Up From The Setup Page In Ten Minutes

The customer brings the product up on their own computer by following the setup page, in under ten minutes and without changing any code.

- **Status:** Active
- **Characteristic:** Flexibility
- **Sub-characteristic:** Installability
- **Business importance:** High
- **Technical risk:** Low

## Scenario

### Source

The customer, who runs the product on their own, as [`CON-02`](../../product-vision.md#con-02) requires.

### Stimulus

The customer wants a working board on their own computer.

### Environment

A computer with Docker installed, a clean checkout of `main`, and a key for the LLM service provider.

### Artifact

The setup page [`docs/setup.md`](../../setup.md) and the containers it starts.

### Response

Following only the setup page, the customer starts every container, opens the board in a browser, and gets an AI block's reply.

### Response Measure

On a first run with no images cached, the board opens and answers a query within 10 minutes of the first command, editing only the LLM key in `app/backend/.env` and no other file.

## QRT-01

A first run of the product by the setup page's steps, with no image cached, opens the board and answers a query in under 10 minutes, changing no file but `app/backend/.env`.

- **Status:** Active
- **Level:** scripted
- **Runs at:** a development machine with Git, Docker, curl, and Python 3: `GROQ_API_KEY=<key> scripts/check_setup_time.sh`.

### Procedure

1. On a development machine with Docker running and port `8090` free, set `GROQ_API_KEY` to a key for the LLM service provider.
2. From the repository root, run `scripts/check_setup_time.sh`.
   The script clones `main` into a temporary directory, removes the base images the product is built from, and builds every layer again, so nothing is cached.
   A base image another container on the machine still uses cannot be removed, and the script prints it as kept.
   It follows the Install, Configure, and Run steps of [`docs/setup.md`](../../setup.md), putting only the key into `app/backend/.env`.
   Then it opens the board, adds an AI block, sends it a query, and finally removes its containers, volume, and images.
3. Read the script's output: the seconds from the clone to the query's answer, the role of the reply, and the files the run changed.

**Pass when:** the reply is the LLM's answer, it arrives in under 600 seconds from the clone, and the only file the run changed is the ignored `app/backend/.env`.
