# ADR-004: Use Self-Hosted OpenPanel For Product Analytics

- **Status:** Accepted
- **Created:** 2026-11-09
- **Updated:** 2026-11-09
- **Containers:** `backend`
- **Addresses:** [`FR-022`](../../functional-requirements/fr/FR-022.md)

## Context

The team needs to understand whether members use the product's core task, as described in [`FR-022`](../../functional-requirements/fr/FR-022.md).
The events and their properties are defined in the [analytics plan](../../analytics.md#the-events).
The product must not send query text, reply text, member identity, block titles, or other free text to the analytics service.
The core task must continue to work when analytics is disabled or OpenPanel is unavailable.

## Considered Options

- **Collect no product analytics.**
  This avoids operating an analytics service, but the team cannot measure whether members use the core task.
- **Send events to a hosted analytics service.**
  This reduces the work of operating the service, but sends product analytics data outside the university network.
- **Self-host OpenPanel and send events from the backend.**
  This keeps the analytics service on the university network and lets the backend send only the events and properties defined in the analytics plan.

## Decision Outcome

Chosen option: self-host OpenPanel on the university network and send the product analytics events from the `backend`.
The backend uses the OpenPanel project configured for its environment.

## Consequences

- **Measurement:** the team can analyze events from the core task using OpenPanel, as specified by [`FR-022`](../../functional-requirements/fr/FR-022.md).
- **Privacy:** the backend sends only the event properties listed in the analytics plan and does not send free text or member identity.
- **Availability:** disabling analytics or losing access to OpenPanel does not stop the core task.
- **Operations:** the team must maintain the self-hosted OpenPanel service.
