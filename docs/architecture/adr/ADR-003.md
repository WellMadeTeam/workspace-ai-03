# ADR-003: Call The LLM From The Backend While The Query Request Waits

- **Status:** Accepted
- **Created:** 2026-10-25
- **Updated:** 2026-10-25
- **Containers:** `backend`, `gateway`
- **Addresses:** [`FR-005`](../../functional-requirements/fr/FR-005.md), [`FR-006`](../../functional-requirements/fr/FR-006.md), [`FR-007`](../../functional-requirements/fr/FR-007.md), [`QR-02`](../../quality-requirements/qr/QR-02.md), [`QR-03`](../../quality-requirements/qr/QR-03.md)
- **Decision:** [`DEC-018`](../../decisions.md#dec-018)

## Context

A query from an AI block is answered by the LLM service provider, and the answer, or the error when there is none, must be stored in the block so every member sees it, per [`FR-005`](../../functional-requirements/fr/FR-005.md), [`FR-006`](../../functional-requirements/fr/FR-006.md), and the customer's [`DEC-018`](../../decisions.md#dec-018).
The provider's key must stay out of the browser, a reply can take tens of seconds, and the checks of [`QR-02`](../../quality-requirements/qr/QR-02.md) must run with no key at all.

## Considered Options

- **The browser calls the provider directly.**
  It needs no backend code, but it sends the key to every member's browser, and the reply is stored only if that browser stays open.
- **A background job: the backend stores the query, answers at once, and a worker fetches the reply later.**
  No request waits on the provider, but it needs a queue or a worker process, which is a fifth container for a product that serves one board of 10.
- **The backend calls the provider while the query request waits.**
  The backend stores the query, calls the provider with the block's conversation and its connected blocks, and stores the reply or the error before it answers the request.

## Decision Outcome

Chosen option: the backend calls the provider while the query request waits, through one service module, `app/backend/src/services/ai_service.py`, and the `gateway` gives that request up to 120 seconds.

## Consequences

- **Fault Tolerance:** a provider failure ends inside the backend, which stores it on the block as an error every member can see, which [`QR-03`](../../quality-requirements/qr/QR-03.md) measures.
- **Testability:** the provider is reached through one module, so the checks replace it and run with no key, which [`QR-02`](../../quality-requirements/qr/QR-02.md) measures.
- **Cost:** a backend worker is busy for the whole wait, and a reply slower than 120 seconds is cut off by the gateway and shown as a failed query.
