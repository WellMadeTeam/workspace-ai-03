# ADR-005: Export Backend Request Signals To OpenObserve Over OTLP/HTTP

- **Status:** Accepted
- **Created:** 2026-11-09
- **Updated:** 2026-11-09
- **Containers:** `backend`
- **Addresses:** [`FR-023`](../../functional-requirements/fr/FR-023.md), [`QR-05`](../../quality-requirements/qr/QR-05.md)

## Context

The system operator needs to diagnose failed requests in the core task, as described in [`QR-05`](../../quality-requirements/qr/QR-05.md).
The backend needs to record request logs and duration metrics, as specified in [`FR-023`](../../functional-requirements/fr/FR-023.md).
The signals need to help an operator find a request by its identifier, route, outcome, and duration.
The signals must not contain request or response bodies, query or reply text, authorization data, secrets, or member identity.
The product must keep working when observability is disabled or OpenObserve is unavailable.

## Considered Options

- **Keep signals only in the backend's local logs.**
  This needs no telemetry service, but an operator cannot search request logs and metrics centrally.
- **Send signals through a service-specific API.**
  This can use the selected service directly, but ties the backend's instrumentation to that service's API.
- **Export OpenTelemetry signals to OpenObserve over OTLP/HTTP.**
  This sends structured request logs and duration metrics through one standard protocol to the selected observability backend.

## Decision Outcome

Chosen option: the `backend` records a structured log for each HTTP request and a histogram of request durations, then exports both to the self-hosted OpenObserve service over OTLP/HTTP.
The staging and production environments send their signals to their corresponding OpenObserve organizations.

## Consequences

- **Diagnosability:** the operator can search for a request and compare its outcome and duration with the `SLI-01` request-duration metric, as required by [`QR-05`](../../quality-requirements/qr/QR-05.md).
- **Privacy:** the backend excludes request and response content, credentials, secrets, and member identity from the exported signals.
- **Availability:** disabling observability or losing access to OpenObserve does not stop the product from serving boards and queries.
- **Operations:** the team must maintain the self-hosted OpenObserve service and its 30-day signal retention.
