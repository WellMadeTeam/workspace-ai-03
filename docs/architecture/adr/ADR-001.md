# ADR-001: Run As A Frontend, A Gateway, A Backend, And A SQLite Database

- **Status:** Accepted
- **Created:** 2026-10-25
- **Updated:** 2026-10-25
- **Containers:** `frontend`, `gateway`, `backend`, `database`
- **Addresses:** [`FR-001`](../../functional-requirements/fr/FR-001.md), [`FR-005`](../../functional-requirements/fr/FR-005.md), [`QR-01`](../../quality-requirements/qr/QR-01.md), [`QR-04`](../../quality-requirements/qr/QR-04.md)
- **Decision:** [`DEC-016`](../../decisions.md#dec-016)

## Context

The customer runs the product on his own computer, per [`CON-02`](../../product-vision.md#con-02), so starting it must take one documented command, as [`QR-04`](../../quality-requirements/qr/QR-04.md) measures.
At most 10 members use one board at a time, per [`CON-03`](../../product-vision.md#con-03), so nothing has to scale past one machine, but every change must reach the other members within two seconds, per [`QR-01`](../../quality-requirements/qr/QR-01.md).
The board is a canvas of draggable blocks, and the backend has to call an LLM service provider with a key the browser must never see.
A team of 4 builds it in a 10-week course, per [`CON-04`](../../product-vision.md#con-04) and [`CON-05`](../../product-vision.md#con-05).

## Considered Options

- **One container: the backend also serves the built frontend.**
  It is one image less, but every frontend change rebuilds the backend image, and the browser's requests and the API share one process with no place to route or time out a slow AI reply.
- **A frontend, a gateway, a backend, and a PostgreSQL database container.**
  A separate database server handles many writers, but 10 members on one board never need that, and it adds a fourth service the customer has to start, configure, and keep a password for.
- **A frontend, a gateway, a backend, and a SQLite database in a volume.**
  The store is one file the backend opens itself, so it needs no server and no credentials, and it survives a restart in a volume.

## Decision Outcome

Chosen option: a frontend, a gateway, a backend, and a SQLite database in a volume, started together by `app/docker-compose.yml`.
The `frontend` is a React single-page application with React Flow for the canvas, the `backend` is Python with FastAPI, the `database` is SQLite, and the `gateway` is nginx, the one public entry point that sends `/api` to the backend and the rest to the frontend.
The record documents the stack the team chose in [`DEC-016`](../../decisions.md#dec-016).

## Consequences

- **Installability:** one `docker compose up --build` and one LLM key bring every container up, which is what [`QR-04`](../../quality-requirements/qr/QR-04.md) measures.
- **Time Behaviour:** SQLite answers a board's reads from a local file, fast enough for 10 members, which [`QR-01`](../../quality-requirements/qr/QR-01.md) measures.
- **Cost:** SQLite lets one writer in at a time, so the product cannot grow past one backend process without changing the `database`, which [`CON-03`](../../product-vision.md#con-03) does not ask for.
- **Cost:** the LLM key lives in the backend's environment file, which the customer creates by hand.
